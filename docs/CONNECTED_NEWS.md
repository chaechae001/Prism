# DB 뉴스와 본문 기반 AI 대화

## 데이터 흐름

```text
기사 제목·본문·URL·언론사·날짜·이용 범위
  → private.prism_cluster_articles (본문 비공개)
군집 ID·대표기사 ID·회원 기사 ID
  → private.prism_cluster_groups / prism_cluster_members
완료 배치 선택
  → private.prism_cluster_heads의 namespace 포인터
  → FastAPI 목록·상세 → 뉴스 피드
선택 뉴스의 DM 질문
  → 같은 namespace·활성 배치·군집 회원 확인
  → 허용된 본문 해시 검증과 문맥 길이 제한
  → 서버의 Elice 제공자 → 답변 출처 ID 검증 → DM 표시
```

기존 `public.articles`, `public.stories`와 새 군집 테이블을 강제로 합치지 않습니다. 군집 배치는 원래 기사 ID를 보존하는 독립 데이터 어댑터로 제공합니다. 현재 API 계약을 유지하고 본문·권한 메타데이터·DB 접속 정보는 뉴스 JSON에 노출하지 않습니다.

## 서버 설정

루트 `.env`에 기존 DB 설정을 유지하고 `backend/.env.chat.local`에 Elice 설정을 저장합니다. 실제 값은 Git에 올리지 않습니다. 설정 이름은 `backend/.env.chat.example`을 참고합니다.

기존 private 군집 저장 스키마와 활성 배치가 필요합니다. 이 실행 방법은 테이블 생성·초기화·뉴스 수집·데이터 덮어쓰기를 수행하지 않습니다. 저장은 [군집 저장](CLUSTER_STORAGE.md), 새 수집 배치와 완료 포인터 갱신은 [수집 작업자](SCHEDULED_NEWS.md)를 참고합니다. 검증 전 스키마 SQL을 기존 DB에 재실행하지 않습니다.

프로젝트 루트에서 읽기 전용 점검을 실행합니다.

```powershell
python -B -m backend.app.connected_news --namespace scheduled-local-test
```

기사·대표기사 수, 선택 뉴스의 허용된 본문 수, 제공자 설정 유무를 출력합니다. 실제 AI를 호출하거나 본문·키를 출력하지 않습니다. 설정 유무 확인은 API 키의 실제 인증 성공을 보장하지 않습니다.

프로젝트 루트에서 API를 실행합니다.

```powershell
./scripts/run-connected-news.ps1
```

다른 터미널에서 프론트를 실행합니다.

```powershell
cd frontend
$env:VITE_API_BASE_URL='http://127.0.0.1:8006'
npm.cmd run dev:http -- --port 5186
```

`http://127.0.0.1:5186/`에서 확인합니다. 포트가 이미 사용 중이면 기존 서버를 Ctrl+C로 종료합니다. 다른 배치는 실행 스크립트의 `-Namespace`로 선택합니다. 두 스크립트의 API 포트와 프론트 주소는 일치해야 합니다.

## 검증 순서

1. 홈에 DB 기사 사진·제목·출처가 나타나는지 확인합니다.
2. 기사 사진을 눌러 상세와 원문 링크를 확인합니다.
3. 게시물 DM 아이콘을 눌러 해당 뉴스 대화방을 엽니다.
4. `이 기사를 세 줄로 요약해줘` 또는 `초등학생도 이해할 수 있게 설명해줘`를 요청합니다.
5. 선택 기사 본문에 나온 구체적 수치·기간에 관해 물어보고 원문과 비교합니다.
6. 다른 사건이나 제공하지 않은 최신 정보는 확인할 수 없다고 답하는지 확인합니다.

## 문맥과 ID 처리

- DB 뉴스 ID는 `namespace + 군집 ID`에 결합됩니다. 회원 기사 ID는 원래 입력 값을 보존합니다.
- 현재 활성 배치에 대응되는 과거 `local-cluster-*` 링크도 상세·북마크·DM에서 해석합니다. 제거되거나 변경된 군집을 다른 뉴스로 바꾸지 않습니다.
- 읽기 전용 트랜잭션에서 군집·대표기사·회원 기사·제목·URL·본문 해시를 확인합니다. 조회 중 배치가 바뀌어 이전 화면과 불일치하면 재조회하도록 안내합니다.
- `collect`, `store`, `summarize`가 모두 allowed인 본문만 사용합니다. unknown/denied를 자동 승인하지 않습니다. 선언값은 언론사 허가 확인 결과를 뜻하지 않습니다.
- 대표기사부터 최대 50개 후보를 살피고 기사당 12,000자·전체 24,000자까지만 LLM 문맥으로 사용합니다. 긴 본문에는 발췌 표시를 전달합니다.
- AI의 출처 ID는 실제로 전달한 본문 ID에 한정합니다. 다른 뉴스나 미전달 본문을 출처로 제시하면 답변을 거절합니다.
- `cluster-local`은 오프라인 파일 미리보기로 유지하며 AI를 호출하지 않습니다. `cluster-db` 대화는 `PRISM_CHAT_ENABLED=1`, `PRISM_CLUSTER_CHAT_ENABLED=1`과 제공자 설정을 명시해야 활성화됩니다. 실행 스크립트가 두 스위치를 프로세스에만 설정합니다.
- 비로그인 DM은 로컬 개발 접속에 제한됩니다. 로그인된 사용자는 허용된 Origin에서 계정당 시간당 30회 한도와 제공자 호출 제한을 적용합니다. 저장된 개인 대화 이력은 외부 LLM에 자동 전송하지 않습니다.

군집 요약·사실 중심 제목 생성과 검토 후 게시, 로그인·계정별 저장은 [요약·평가·계정 기능](EDITORIAL_AND_ACCOUNTS.md)에 설명합니다. DM 요약 요청은 대화 답변이며 메인 요약 게시 상태를 변경하지 않습니다.

## 비회원 실행과 후속 기능

연결 스크립트는 비회원 모드로 실행합니다. 로그인·회원가입·인증 메일은 현재 단계에서 사용하지 않으며 북마크·댓글·DM은 브라우저에 저장합니다. 다른 기기와 동기화되지 않습니다. 계정 코드는 보존하며 추후 인증 개발을 재개할 때만 `-EnableAccounts`를 명시합니다. `-DisableAccounts`는 명시적 비활성 옵션으로 유지하며 두 옵션을 함께 주면 비활성이 우선합니다.

음성 기능은 후속 개발로 보류했습니다. 현재 실행에는 음성 API 키가 필요하지 않습니다.
