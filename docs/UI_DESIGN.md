# PRISM UI/UX 방향과 참고 자료

## 방향: 차분한 편집 지면 + 확인 가능한 근거

‘빨리 클릭하게 만드는 뉴스’보다 ‘같은 사건을 비교하고 이해하는 뉴스’에 맞춥니다. 메인에는 사건을 카드로 묶고, 상세에서는 **핵심 요약 → 관점 비교 → 출처 확인**을 같은 맥락에서 이동하게 합니다. 첫 화면의 수많은 필터 대신 카테고리·검색·정렬만 우선 제공합니다.

이번 구현의 서비스 이름은 임시 브랜드 **프리즘(PRISM)**입니다. 밝은 종이 배경, 짙은 녹색, 얇은 구분선, 여백과 기사 제목 중심의 편집 레이아웃으로 제작했습니다. 카테고리와 관점의 색을 정치 성향과 연결하지 않았습니다. 사진 이용 권한이 아직 없는 단계여서 SVG 일러스트를 직접 작성했습니다.

## 레퍼런스 추천

2026-10-21 공식 서비스/문서를 확인했습니다. 전체 화면을 복제하기보다 아래 상호작용을 참고하세요.

| 참고 | 가져올 아이디어 | 이 서비스에 적용하는 방법 |
|---|---|---|
| [Ground News](https://ground.news/) | 같은 사건을 여러 출처로 비교하는 탐색 방식 | 사건 카드에 기사 수·출처 수, 상세에서 비교 경로 제공 |
| [AllSides](https://www.allsides.com/unbiased-balanced-news) | 동일 주제의 서로 다른 강조점을 나란히 보기 | 쟁점 설명+각 설명의 기사 근거. 해외 성향 라벨을 국내 언론사에 그대로 적용하지 않음 |
| [Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction) | 접근성·키보드 동작을 갖춘 UI 기반 | 이번 코드에 Dialog·Tabs·Slider 실제 적용 |
| [shadcn/ui](https://ui.shadcn.com/docs/installation/vite) | 코드 소유형 컴포넌트·추후 확장 패턴 | 팀이 Tailwind 체계를 원할 때 대안. 현재 구현은 Radix+CSS로 통일 |

Ground News와 AllSides는 비교 UX 참고이며 특정 서비스의 중립성이나 라벨 정확성을 보증하는 추천이 아닙니다. 레퍼런스의 분류 정책과 우리 팀의 한국어 뉴스 분류 정책은 별도로 정의해야 합니다.

## 오픈소스 UI 라이브러리 선택

**현재는 Radix UI를 사용했습니다.** 뉴스 화면의 핵심은 카드·타이포그래피이므로 화면 전체를 무거운 테마로 묶기보다, 동작이 복잡한 부품만 라이브러리를 사용하는 방식입니다. Radix는 스타일을 강제하지 않으므로 AI가 만든 디자인을 수정하기도 쉽습니다. [소개](https://www.radix-ui.com/primitives/docs/overview/introduction), [Dialog](https://www.radix-ui.com/primitives/docs/components/dialog), [Tabs](https://www.radix-ui.com/primitives/docs/components/tabs), [Slider](https://www.radix-ui.com/primitives/docs/components/slider)

- Dialog: 상세 화면, 배경 비활성화, Escape, 포커스 처리.
- Tabs: 요약/관점/출처, 키보드로 이동 가능한 탭.
- Slider: 탐색의 폭 0~100, 키보드 조절.
- Lucide React: 검색·북마크·출처·탐색 등 아이콘.
- CSS: 반응형 지면과 디자인 토큰. CSS-in-JS나 별도 전역 상태 라이브러리 없이 시작했습니다.

Tailwind/shadcn으로 바꾸고 싶다면 컴포넌트 단위로 전환하세요. Radix·다른 종합 UI 라이브러리를 화면마다 섞는 것은 토큰·상태 표현의 일관성을 유지하기 어렵게 만듭니다. 라이선스 원문은 설치 패키지와 lockfile 버전을 기준으로 보관하세요.

## 디자인 토큰

| 항목 | 값/원칙 |
|---|---|
| 전체 배경 | `#faf9f6` |
| 카드 배경 | `#ffffff` |
| 기본 텍스트 | `#242b26` |
| 주요 액션 | `#245c43` |
| 구분선 | `#e4e5de` |
| 제목 | 짧고 구체적으로, 사건의 핵심을 표현 |
| 글꼴 | Noto Sans KR / DM Sans, 로컬 시스템 폴백 |
| 모서리 | 카드 8px, 상세 13px |
| PC 구조 | 기사 영역 + 사이드 탐색 패널 |
| 모바일 구조 | 카테고리 → 탐색 폭 → 뉴스 목록 → 분포 |

현재 구현은 프로토타입 수준으로 정보 밀도가 높습니다. 실제 공개 전 최소 글자 크기·명도 대비·터치 영역을 실기기로 점검하고, 긴 실제 제목·원문 출처명·키보드 포커스 복귀까지 확인하세요. 자동 생성 UI도 사람이 읽기 편한지가 우선입니다.

## 페이지별 사용 흐름

1. **메인:** 오늘의 브리핑, 사건 카드, 출처 수, 추천 이유. 날짜는 fixture 에디션임을 명시.
2. **카테고리:** 같은 피드의 `category` URL 상태로 구현. 카드 형태는 재사용.
3. **검색:** 검색어 확정 후 조회, 결과 수·빈 결과·원래 목록 복귀.
4. **사건 상세:** URL `story`로 직접 접근 가능한 Dialog. 요약과 관점, 원문 목록을 탭으로 제공.
5. **저장한 뉴스:** 북마크한 사건을 다시 조회. 이 브라우저에만 저장된다고 표시.

기능정의서의 ‘요약 페이지’와 ‘상세 페이지’는 MVP에서 같은 사건 상세의 두 탭으로 합쳤습니다. 중간 요약 페이지를 따로 거치지 않아도 되게 한 선택입니다. 공유/검색 노출이 중요해지면 `/stories/{id}` 독립 페이지로 확장할 수 있으며, API는 이미 사건 ID로 조회합니다.

## 상태별 필수 표현

| 상태 | UI |
|---|---|
| 목록 로딩 | Skeleton, 기존 조건과 요청 중인 조건 혼동 방지 |
| 빈 결과 | 다른 키워드 제안, 전체 뉴스 복귀 |
| API 실패 | 다시 시도, 요청 ID |
| 요약 대기 | 준비 중 배지, 출처는 접근 가능 |
| 출처 부족 | 확정 요약을 만들지 않고 보류 이유 |
| 요약 실패 | 실패 상태, 원문 목록 접근 |
| 근거 선택 | 출처 탭으로 이동, 해당 기사 강조 |
| 피드백 성공 | 데모 수신이며 영구 저장하지 않는다고 표시 |

프론트에 있는 ‘개발 도구’는 개발 시나리오 테스트용이며 실서비스 사용자의 화면에서는 제거합니다.

## 프론트엔드를 AI에 맡길 때 복사할 지시문

> PRISM의 기존 React+Vite+TypeScript 프로젝트를 수정해줘. Radix UI Dialog/Tabs/Slider, TanStack Query, Lucide를 유지해줘. API 계약은 contracts/openapi.json이고 타입은 src/api/schema.d.ts에서 가져와. 컴포넌트 안에 기사 JSON을 하드코딩하지 말고 src/api/client.ts의 API를 사용해줘. 검색·카테고리·정렬·탐색 폭·사건 ID는 URL 상태로 관리해. 카드 하나는 기사 하나가 아니라 사건 하나야. 상세에서 요약 문장별 근거 기사, 서로 다른 쟁점, 원문 출처를 확인할 수 있어야 해. 데이터가 없는 상태·요약 준비 중·출처 부족·API 오류·잘못된 사건 ID도 처리해. 정치 성향/중립 점수를 임의 생성하지 말고, demo/unverified 라벨을 숨기지 마. PC와 모바일에서 읽을 수 있게 하고 키보드와 포커스를 확인해줘. 응답 필드가 부족하면 임의로 API를 바꾸기 전에 계약 변경 내용을 설명해줘. 끝나면 TypeScript 검사, build, 기존 계약 테스트와 실제 브라우저 동작을 확인해줘.

AI 결과를 리뷰할 때는 ‘예쁜가’뿐 아니라 근거 링크가 실제 ID를 참조하는지, 로딩과 빈 결과가 구분되는지, 필터를 바꾼 뒤 이전 페이지가 섞이지 않는지, 가상 데이터를 사실처럼 보여주지 않는지를 확인하세요.
