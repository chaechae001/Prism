# 딥그린 뉴스 피드 / 마이페이지 인계

## 화면과 코드 구조

- `frontend/src/App.tsx`: 메뉴, 오늘 날짜 고정 헤더, 검색·카테고리·추천 설정, 날짜 탐색, 화면 전환.
- `frontend/src/components/TimelineCard.tsx`: 명조 헤드라인, 기사 설명, 투명한 언론사 이름 칩, 출처 보기, 북마크. 섬네일을 제거해 텍스트에 집중한다.
- `frontend/src/components/MyPage.tsx`: 로컬 프로필 설정, 열람 현황, 차트, 보관함.
- `frontend/src/components/ReadingCharts.tsx`: 밸런스 게이지·주제 링·최근 7일 막대그래프. 그래프마다 수치를 읽을 수 있는 접근성 설명을 제공한다.
- `frontend/src/hooks/useReaderActivity.ts`와 `frontend/src/presentation/reading.ts`: 로컬 기록 저장과 집계.
- `frontend/src/styles.css`: 딥그린 `#1A3A2B`, 미색 `#F8F9FA`, 본문 `#212529`, 저채도 차트 색상. Noto Serif KR / Noto Sans KR을 사용하며 네트워크가 없으면 시스템 폰트로 대체한다.
- 기존 Radix Dialog/Tabs, TanStack Query, Lucide를 사용한다. 새 런타임 라이브러리는 추가하지 않았다.

## 지금 실제로 동작하는 기능

1. 진입하면 한국 시간의 오늘 업데이트된 사건을 표시한다. URL의 날짜·기간 지정도 유지한다. 수집일·발생일이 아니라 기존 `story.updated_at` 기준이다.
2. 카드 제목은 API의 `story.title`을 사용한다. 프론트에서 감정적 표현을 재작성하거나 중립성을 판정하지 않는다. 중립적 대표 제목 생성·검증은 분석/백엔드에서 담당한다.
3. 언론사 칩은 기사 배열의 `publisher_id`로 중복 제거한 이름이다. 칩을 누르면 상세의 출처 탭이 열린다. 로고가 없는 데이터에 임의의 실제 언론사 로고를 넣지 않는다.
4. 북마크는 기존 `prism:v1:saved` 저장소를 계속 사용하며 마이페이지의 보관함에서 확인한다. 이전 `?view=saved` 주소도 마이페이지로 해석한다.
5. 상세 API가 성공해 사건이 표시되면 열람을 기록한다. 같은 사건은 한국 시간 하루에 한 번 집계한다. 최근 7일의 주제 분포·날짜별 건수를 계산한다.
6. 프로필 이름(20자), 기록 저장 켜기/끄기, 열람 기록 삭제(화면 내 재확인)를 제공한다. 북마크는 기록 삭제와 별개다.

## 점수와 통계의 의미

- 밸런스 스코어의 기본값은 **점수 없음 / 평가 준비 중**이다. 평가 모델·산식·검증 자료가 없기 때문이다.
- 사용자가 디자인 예시 버튼을 눌렀을 때만 82/100을 표시하고, 실제 분석 결과가 아님을 게이지·배지·접근성 설명에 명시한다. 예시 점수는 사용자 통계에 저장하지 않는다.
- 출처 수는 **열람한 사건에 연결된 출처의 고유 개수**다. 사용자가 원문을 클릭한 수가 아니다.
- 주제별 색상은 기사 카테고리이며 정치 성향 분류가 아니다. 100점이나 카테고리 균등 분포를 객관적 중립성의 증거로 취급하지 않는다.
- 통계는 상세 화면을 연 기록이며 완독·독서 시간은 측정하지 않는다. 가상 뉴스가 포함되면 건수를 별도로 표시한다.
- 기록은 이 브라우저에만 저장한다. 계정 인증·기기간 동기화·실제 편향 분석은 구현하지 않았다. 저장이 실패하면 안내한다.
- `prism:v1:reader`는 버전 1 형식이며 최근 500개 기록까지 보관한다. 7일 안에 500건을 초과해 열람하면 오래된 기록이 빠져 통계가 일부 누락될 수 있다. 실제 운영 단계에서는 서버 집계로 전환한다.

## 백엔드 담당자에게

**현재 API·DB·공유 계약 변경은 없다. 기존 목록/상세 응답을 그대로 연결하면 된다.**

첫 DB 연결 목표(가상 사건 1개+기사 3개)를 우선 유지한다. 이번 화면 때문에 추가 API 개발을 먼저 할 필요는 없다.

후속으로 협의할 사항:

- 현재 날짜 필터는 불러온 페이지에만 적용한다. 전체 기간 조회가 필요하면 목록 API의 날짜 기준과 요청 필드를 함께 합의해야 한다. 현재 프론트는 날짜 필드를 API에 전송하지 않는다. 이전 날짜의 fixture를 사용하는 날에는 빈 오늘 화면이 정상이며 달력의 전체 날짜로 확인할 수 있다.
- 밸런스 평가를 붙이기 전에 측정 대상·평가 기간·데이터 충분성·산식·모델 버전·불확실성을 정의한다. 실제 점수와 평가 대기 상태를 구분할 계약이 필요하다.
- 로그인/계정 설정, 북마크 동기화, 열람 이벤트 저장은 별도 후속 작업이다. 로그인 화면이나 인증이 완료된 것처럼 표시하지 않는다.
- 실제 데이터의 `coverage.publisher_count`와 기사 배열의 고유 출처 수를 일치시킨다. UI의 언론사 칩은 기사 배열 기준이다.

## 실행

PowerShell에서 프로젝트의 `frontend` 폴더로 이동한 뒤:

```powershell
npm.cmd install
npm.cmd run dev
```

기본 주소: `http://127.0.0.1:5173/`. 기본 모드는 브라우저 MSW Mock이다. API 서버 연결 설정은 기존 `.env.example` 및 API 문서를 따른다.

```powershell
npm.cmd test
npm.cmd run build
```

실제 DB·로그인·밸런스 평가 모델과의 연결 검증은 별도로 진행해야 한다.
