# PRISM 소셜 뉴스 UI · 2026-10-22

이 문서는 첫 소셜 UI 버전 기록입니다. 최신 변경인 달력 제거·날짜 스토리·라이트/다크·댓글·기사별 실제 LLM 연결은 [뉴스 DM 안내](NEWS_DM_SETUP.md)를 우선 확인해 주세요. 아래 AI 준비 화면·달력 설명은 이전 버전입니다.

## 실행

프로젝트의 `frontend` 폴더를 VS Code 터미널에서 열고 실행합니다.

```powershell
$env:VITE_API_MODE='mock'
$env:VITE_NEWS_API_VERSION='v1'
npm.cmd run dev -- --port 5183
```

브라우저에서 http://127.0.0.1:5183/ 에 접속합니다. 현재 화면 확인에는 Supabase·네이버 키·크롤링 봇이 필요하지 않습니다. Mock은 가상 사건/요약이며, 사진은 사건과 무관한 예시입니다. 새 터미널에서 환경 변수를 다시 지정하지 않으면 기존 `.env.local` 설정이 적용될 수 있습니다. 위 명령은 파일에 저장한 설정을 덮어쓰지 않습니다.

실제 FastAPI 연결은 기존 연결 가이드의 `npm.cmd run dev:http`를 사용합니다. 이번 UI 작업은 기존 API 형식과 backend/database를 변경하지 않았습니다.

## 화면과 동작

| 위치 | 구현 |
|---|---|
| 홈 | 흰 배경, 원형 최근 뉴스, 매체/날짜 헤더, 큰 사진, 제목, AI 요약 또는 원문 미리보기, 출처·공유·북마크 |
| 최근 뉴스 | 현재 로드한 기사 중 최신순 최대 10건. 전체 화면에서 이전/다음 버튼, 좌우 키, 터치 스와이프, 저장, 상세 이동. 자동 넘김 없음 |
| 두 번째 메뉴 | 전체·정치·경제·사회·기술 필터. 기존 category 요청 재사용 |
| 가운데 메뉴 | AI 대화 소개와 예시 질문. '추후 추가 예정' 명시, 실제 LLM 전송 없음 |
| 네 번째 메뉴 | 사진만 배치한 3열 탐색 격자, 검색창, 사진 클릭 시 기존 기사 상세 |
| 맨 오른쪽 메뉴 | 브라우저에 북마크한 기사 목록. 기존 독서 통계·계정 설정은 화면에서 제외하고 추후 추가 예정 표시 |
| 날짜 | 상단 달력 아이콘 → 기존 날짜·기간 필터 |
| 상세 | 기존 요약·출처·다른 관점·추가 분석 탭과 원문 링크 유지 |
| 연결 설정 | 모바일 우하단 작은 설정 아이콘 또는 PC 왼쪽 메뉴. 추천 방식·다양성·Mock 상태·API 연결 정보 유지 |

북마크는 기존 `prism:v1:saved` 키를 그대로 사용합니다. 로그인/다른 기기 동기화 기능은 아직 없습니다. 기사 공유는 브라우저 공유 기능 또는 링크 복사이며 다른 사람에게 자동 전송하지 않습니다.

모바일은 하단 5개 메뉴, 중간 폭은 왼쪽 아이콘 메뉴, PC는 왼쪽 내비게이션 + 중앙 피드 + 오른쪽 최근 뉴스로 전환합니다. Radix Dialog, TanStack Query, Lucide 등 기존 오픈소스를 재사용했습니다.

## 사진과 본문 연결: 최민준님·분석가 협의 요청

네이버 API 연동은 중단합니다. 기존 RSS 기사와 크롤링 본문을 원문 URL/기사 ID로 연결하는 방향입니다. 아래는 **다음 작업의 제안**이며 현재 API 필드에 추가한 것이 아닙니다.

분석가께서는 우선 아래와 같이 기사 3건 정도의 JSON 샘플을 제공해 주세요.

```json
{
  "article_id": "기존 RSS article_id (알 수 없으면 null)",
  "original_url": "https://publisher.example/news/article-123",
  "body_text": "HTML·메뉴·광고를 제거한 기사 본문",
  "content_status": "full_text",
  "fetched_at": "2026-10-22T14:00:00+09:00",
  "published_at": "2026-10-22T10:00:00+09:00",
  "extractor_version": "publisher-parser-v1",
  "image": {
    "url": "https://publisher.example/media/article-123.jpg",
    "alt": "사진 설명",
    "credit": "사진 제공자",
    "display_allowed": false
  },
  "usage": {
    "store_allowed": false,
    "analysis_allowed": false,
    "full_text_display_allowed": false,
    "evidence": "실제로 확인한 이용 근거"
  }
}
```

`false`는 샘플 기본값입니다. 실제 확인한 범위에 맞게 작성해 주세요. 원문·본문 저장, 분석, 본문 재표시, 이미지 재표시는 각각 구분해 주세요. 추출이 실패하면 빈 본문을 성공 처리하지 않고 `failed` 또는 `excerpt`로 표시해 주세요. 기사 전문을 확보해도 화면에는 허용된 내용만 표시합니다.

최민준님께서는 기존 RSS 테이블을 기준으로 먼저 기사 매칭과 본문 보관 위치를 검토해 주세요. URL 정규화 규칙, 본문 재수집 시 버전, 실패 상태를 정하고, 기존 목록/상세 JSON은 유지해 주세요. 사진을 프론트에 전달하려면 선택 필드 `media` 등의 추가 계약을 먼저 협의해 주세요. 이미지 URL의 HTTPS/허용 호스트와 실제 재표시 가능 여부를 서버에서 확인해 주세요.

정채은은 샘플과 합의된 선택 필드가 도착하면 `NewsPhoto`의 실제 기사 이미지 어댑터와 상세 본문 표시를 연결합니다. **현재는 실제 뉴스에 외부 사진을 임의로 붙이지 않습니다.** 실제 API에 사진 필드가 없어 실제 뉴스는 '기사 사진이 제공되지 않았습니다' 대체 화면을 표시합니다. 데모에만 Unsplash 예시 사진을 쓰며 외부 이미지 로딩 실패 시에도 대체 화면을 표시합니다.

## 작업 중단 시점 기록

이전 네이버 작업에서 개발 Supabase에 이미 만든 `private.news_v2_*` 9개 테이블은 삭제하지 않았습니다. 당시 마이그레이션은 SQL 편집기로 적용됐고 CLI 이력 등록은 하지 않았습니다. 기존 RSS/public 테이블은 그대로입니다. 이번 화면 변경은 새 v2 데이터 구조로 전환할 것을 요구하지 않습니다. 기존 v1을 사용해 계속 작업하시면 됩니다.

이전 작업의 임시 API(8003)·UI(5182)와 임시 PostgreSQL 컨테이너는 종료했습니다. 실제 Supabase 데이터는 삭제하지 않았습니다.

PRISM 이름과 기존 뉴스 데이터를 사용하며, 뉴스의 출처·요약 상태·가상 자료 표시는 유지합니다.
